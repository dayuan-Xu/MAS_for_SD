# 编码任务交付物检查指南

## 概述

本指南用于检查工程师 David 的编码任务交付物，分两种情况：

1. **普通编码任务**
2. **代码质量验证脚本编写任务**：一种特殊的编码任务

---

## 一、普通编码任务交付物检查

### 1.1 完整性检查

- [ ] **是否有对应的功能性代码文件**：实现业务逻辑，不包含 pass、TODO 等占位符
- [ ] **是否有对应的测试代码文件**：
    
    单元测试：测试每个函数/方法的正确性
    
    集成测试：测试多个模块间的协作（如果已有多个相关联的模块）
- [ ] **DEVLOG.md 是否已更新**：记录本次编码任务完成情况

### 1.2 交付成果保存位置准确性检查

- [ ] 代码：`/warehouse/{workspace}/frontend/` 和 `/backend/`
- [ ] DEVLOG.md: `/warehouse/{workspace}/DEVLOG.md`

---

## 二、代码质量验证脚本编写任务交付物检查

### 2.1 检查流程

1. **读取验证脚本说明文档**
    
    1. 读取 `./scripts/code_deliverables_check/README.md`
    2. 若不存在 → 直接反馈'不通过'
    
2. **读取验证脚本汇总文件**
    
    1. 读取 `./scripts/code_deliverables_check/summary.json`，若不存在 → 直接反馈'不通过'
    2. 若存在，查看 `overall_passed` 字段：如果为 `false` → 直接反馈'不通过'
    
3. **抽样执行验证脚本**
    
    随机选择某些验证脚本执行，读取脚本结果，决定是否通过

4. **必要时查看详细报告**
    
    1. 优先查看验证脚本的自动化结果（summary.json）
    2. 只在必要时查看详细报告（tests.xml、lint_report.json 等）
    3. 避免直接阅读大量源文件（除非发现脚本结果可疑）

### 2.2 特殊情况处理

**如果验证脚本本身无法运行** → 视为交付物不通过，要求工程师修复脚本

**如果验证脚本覆盖率不足** → 要求完善验证脚本

### 2.3 交付成果保存位置准确性检查

- [ ] 验证脚本：`/warehouse/{workspace}/scripts/code_deliverables_check/`
- [ ] 验证脚本说明文档 README.md：同上目录

---
