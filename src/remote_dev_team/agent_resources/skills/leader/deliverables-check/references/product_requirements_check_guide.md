# 产品需求阶段交付物检查指南

## 一、文档元数据（YAML Frontmatter）

- [ ] 必须包含以下字段：
  ```yaml
  ---
  title: [产品名称]-PRD
  version: x.y.z（例：1.0.0，迭代时递增，如 1.1.0）
  author: Alice/产品经理
  date: YYYY-MM-DD
  state: 评审中/已通过
  ---
  ```

## 二、正文内容结构

### 2.1 需求概述与产品定义

- [ ] **原始需求**：Tim转达的用户需求信息
- [ ] **用户故事**：忠实原始需求，给出用户故事
  
     格式："作为 [角色]，我想要 [功能] 以便 [价值]"
     示例："作为玩家，我想要存档功能以便下次继续游戏"

### 2.2 技术规格

- [ ] **业务逻辑模型**：软件的预期使用流程，使用 Mermaid 流程图表达，可有多个，至少1个
- [ ] **UI 原型**：基本布局的文字描述
- [ ] **功能需求列表**：
  
    - 条目格式：编号（例如REQ-P3-001-v3）- 功能需求内容 - 明确的验收标准
    - 示例："支持登录"→"用户可输入用户名密码登录，错误密码显示提示"
    - 措辞：仅使用"必须（P0 级）/应该（P1 级）"两级措辞
    - 排序：按优先级排序

## 三、质量标准

- [ ] **需求表述规范**：仅使用"必须/应该"两级措辞
  
    "必须"：P0 级，缺失则软件不完整，无法上线
    
    "应该"：P1 级，强烈建议
- [ ] **可验证性**：每个功能需求都有明确的验收标准
- [ ] **可视化**：包含 Mermaid 流程图（至少1个）
- [ ] **专注需求分析**：不涉及技术实现细节

---

**评审重点：**

- 用户故事是否忠实于原始需求
- P0/P1功能是否都有明确的验收标准
- 功能需求列表是否按优先级排序
- 是否仅关注已知需求，未假设用户未提出的需求
- 是否不考虑非功能性需求

**不通过反馈模板：**

```
【存在问题】
1. ...
2. ...

【修改要求】
1. ...
2. ...
```
