## 规则约束-代码质量标准

### 一、正确性与完整性

- 功能符合《系统详细设计.md》中当前编码任务对应的任务描述
- 不包含 pass、TODO 等占位符内容

### 二、规范性与可读性

#### Python 代码

- 严格遵循PEP8和Google Style指南
- 使用 type hints 进行类型注解

#### TypeScript/JavaScript 代码

- 遵循 ESLint 规范
- 使用 TypeScript 类型系统

#### **命名清晰**：变量、函数、类名要有意义

- 好：`calculate_total_price()`
- 差：`calc()`

#### **适当的注释**：

- 为复杂逻辑添加注释
- 解释"为什么这样做"而非"做了什么"

#### **合理的函数长度**：

- 建议单函数不超过 50 行（除非有充分理由）
- 超过 50 行考虑拆分

#### **代码格式**：

- 一致的缩进和空格
- 适当的空行分隔逻辑块

### 三、模块化

- **单一职责**：每个函数/类只做一件事
- **高内聚低耦合**：相关功能组织在一起，减少模块间依赖
- **清晰的接口**：模块间通过明确定义的接口通信

### 四、健壮性

- **边界检查**：检查输入参数的有效性
  
- **错误处理**：使用 try-except 捕获异常
  
- **日志记录**：使用 logging 模块记录关键操作，info级别及以上写入console，debug级别及以上写入日志文件

## 规则约束-测试标准

### 一、单元测试

- 覆盖核心逻辑
- 每个公共函数/方法都有对应的测试
- 使用断言验证预期行为

### 二、集成测试

- 验证模块间协作
- 测试端到端流程
- 使用 mock 隔离外部依赖

### 三、测试技术

- 推荐使用pytest进行python代码测试
- 标准1：运行单个测试文件，必须先切换工作目录（`cd "./warehouse/project1/app/tests/"`）到测试文件所在目录，之后运行`python -m pytest test_example.py`
- 标准2：运行一整个测试目录，比如在文件系统根目录下执行`python -m pytest "./warehouse/project1/app/tests/"`

### 四、测试结果保存

- 每个编码任务的测试必须通过，同时测试结果保存到DEVLOG.md之外的文件（自行决定文件名），在DEVLOG.md中明确说明保存位置

## **执行工具`execute`**：

- **调用execute工具前必须进行Shell 类型检测**：执行 `echo %COMSPEC%`

    - 输出包含 `cmd.exe` → Windows CMD
    - 输出为空或报错 → 可能是 Linux Bash

- **⚠️调用execute工具执行shell命令时的铁律**：

    - **文件系统工具**（`ls`、`read_file`、`write_file` 等）：可以使用绝对路径 `/warehouse/...`
    - **execute 工具**（执行 shell 命令）：**命令中绝对不能**使用以 `/` 开头的绝对路径，必须使用**相对路径**
    - **为什么？**execute 工具最终启动的shell终端的工作目录是虚拟文件系统根目录 `/`，但它映射到真实文件系统的某个目录。如果你使用 `/warehouse/...`，系统会尝试访问真实文件系统的根目录下的 warehouse，这会导致"文件未找到"错误
    - 示例：
        - ✅ 正确：`cd "./warehouse/gomoku_game_v1_2026-04-07_10-00/gomoku/tests" && python -m pytest ./ -v`
        - ✅ 正确：`python -m pytest "warehouse/gomoku_game_v1_2026-04-07_10-00/gomoku/tests/test_pytest.py" -v`
        - ❌ 错误：`python -m pytest "/warehouse/gomoku_game_v3_2026-04-09_17-08/gomoku/tests/" -v`
        - ❌ 错误：`python -m pytest "/warehouse/gomoku_game_v3_2026-04-09_17-08/gomoku/tests/test_pytest.py" -v`

- **每次调用 execute 工具前，必须在 <think> 标签中自我检查：**

    1. 我要执行的命令中包含路径吗？
    2. 这个路径是以 `/` 开头的吗？
    3. 如果是，我必须将其改为相对路径（去掉开头的 `/`，或加上 `./` 前缀）
    4. 我是否应该先用 `cd` 切换到目标目录？

    **违反此规则的后果：命令执行失败，浪费迭代次数，可能导致项目终止！**
