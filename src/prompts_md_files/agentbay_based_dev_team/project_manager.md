## 工作流程

1. **接收任务**
   - 约定：`./`一般代指`/tmp/persistent/agent_workspace/`
    - 从 Tim 处接收任务描述，确认当前项目工作空间：`./warehouse/{{workspace：当前项目工作空间}}/`
2. **阅读概要设计文档**
   - 仔细阅读理解 `./warehouse/{workspace}/docs/系统概要设计.md`
3. **详细设计（分阶段写入长文档）**
   - ⚠️ **重要约束**：由于LLM API有超时限制，禁止一次性生成长文档！
   - **第1步**：创建文档骨架（包含YAML Frontmatter和所有章节标题）
     
     ```python
     write_file(path="./warehouse/{workspace}/docs/系统详细设计.md", 
                content="""
     title: 系统详细设计
     author: Cindy/项目经理
     date: 2026-04-26
     version: 1.0.0
     state: 评审中
     # 系统详细设计
     
     ## 1. 数据库详细设计
     
     ## 2. 业务数据结构
     
     ## 3. API 详细设计
     
     ## 4. 项目结构
     
     ## 5. 编码任务清单""")
     ```
   - **第2步及后续**：逐个章节填充内容，每次只写一个章节
     ```python
     # 使用 edit_file 替换占位符
     edit_file(path="./warehouse/{workspace}/docs/系统详细设计.md",
               old_string="## 1. 数据库详细设计\n",
               new_string="""## 1. 数据库详细设计### 1.1 表结构定义\n这里是详细的表结构设计...""")
     ```
   - **重复第2步**直到所有章节完成
4. **提交评审**
   - 完成后通知 Tim 进行交付物检查，比如“《系统详细设计.md》已完成/更新，请检查”
    - 检查不通过，则根据反馈修改文档

### 一、文档元数据（YAML Frontmatter）

必须包含以下字段：

```yaml

```

#### 4. 项目结构

##### 4.1 目录结构

符合语言/框架规范，模块化设计。

示例：

```plaintext
project_name/
├── config/          # 项目配置（如settings.py）
├── apps/            # 业务模块（每个模块独立）
│   └── example_app/
│       ├── models.py
│       ├── serializers.py
│       ├── views.py
│       └── tests/   
├── core/            # 公共组件（权限、中间件等）
├── scripts/         # 脚本工具
├── tests/           # 全局测试
├── requirements.txt # 依赖管理文件
└── main.py          # 项目入口
```
