# 系统详细设计阶段交付物检查指南

## 一、文档元数据（YAML Frontmatter）

- [ ] 必须包含以下字段：
  ```yaml
  ---
  title: 系统详细设计名称
  author: Cindy/项目经理
  date: YYYY-MM-DD
  version: x.y.z（例：1.0.0，迭代时递增，如 1.1.0）
  state: 评审中/已通过
  ---
  ```

## 二、数据库设计（若需要）

### 2.1 ER 图

- [ ] 是否使用 Mermaid erDiagram 语法

### 2.2 表结构

- [ ] 表名是否使用蛇形命名法
- [ ] 字段列表是否完整：字段名、数据类型、约束（主键/外键/非空/唯一）、注释
- [ ] 是否包含索引设计说明：哪些字段需要索引及原因

### 2.3 表间关系说明

- [ ] 是否说明一对一、一对多、多对多关系
- [ ] 是否说明外键约束和级联操作

## 三、业务数据结构

### 3.1 类图

- [ ] 是否使用 Mermaid classDiagram 语法，表达类关系

  继承关系：`<|--`

  组合关系：`*--`

  依赖关系：`..>`

### 3.2 Pydantic 数据模型

- [ ] 是否为关键数据结构提供带类型注解的 Pydantic 模型

## 四、API 设计（若需要）

### 4.1 RESTful 端点定义

- [ ] 是否对每个端点说明：

  方法：GET/POST/PUT/DELETE

  路径：`/api/v1/users/{user_id}`

  请求格式：请求体 JSON schema

  响应格式：成功/失败的响应示例

### 4.2 三层架构

- [ ] 是否有**路由层**（Routes）：处理 HTTP 请求和响应
- [ ] 是否有**业务逻辑层**（Services）：实现核心业务逻辑
- [ ] 是否有**数据访问层**（Repositories）：数据库操作

### 4.3 错误处理

- [ ] 是否统一错误码定义
- [ ] 是否有异常处理机制
- [ ] 是否有错误响应格式

## 五、项目结构

### 5.1 目录结构

- [ ] 是否符合语言/框架规范，模块化设计

## 六、编码任务清单

- [ ] 是否以表格形式列出所有编码任务，单个任务对应一个源文件：

  序号 | 模块 | 任务描述 | 优先级 | 依赖项
- [ ] 任务描述是否清晰，是否明确指出需要创建的文件
- [ ] 优先级与《产品需求.md》中的 P0/P1/P2是否 对应
- [ ] 依赖项是否用序号表示，形成依赖图

---

**评审重点：**

- 工程师能否直接根据文档编码，无需额外询问
- 所有设计决策是否有明确理由
- 复杂逻辑是否有序列图说明
- 是否覆盖《系统概要设计.md》中的所有模块
- 每个 P0/P1 功能都有对应的详细设计
- 是否与《产品需求.md》和《系统概要设计.md》保持一致
- 棕地开发时是否确保新设计与原有代码兼容并标注新增/变更的设计

**不通过反馈模板：**

```
【存在问题】
1. ...
2. ...

【修改要求】
1. ...
2. ...
```
