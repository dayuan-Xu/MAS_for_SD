# 基于多智能体协同的软件自主开发平台V1.0说明书

---

## 1. 引言

### 1.1 项目背景

随着人工智能技术的飞速发展，大语言模型（LLM）在软件开发领域展现出巨大的应用潜力。然而，单一智能体在面对复杂软件开发任务时，往往存在能力局限，难以独立完成需求分析、设计、编码、测试等全流程工作。基于此背景，本项目提出一种基于多智能体协同的软件自主开发平台，通过构建专业化的智能体团队，实现从软件需求到可交付产品的端到端自动化开发。

### 1.2 技术目标

本平台旨在实现以下技术目标：

- **智能化需求分析**：自动理解用户原始需求，分层定义软件功能，生成可执行的开发任务列表。
- **自动化代码实现**：基于定义的功能点，自动完成代码编写、测试和调试。
- **质量保证机制**：通过独立的评审智能体，确保代码质量和功能正确性。
- **多智能体协作**：建立分工明确、协作有序的智能体团队工作模式。
- **灵活的开发模式**：支持绿地开发（从零开始）和棕地开发（基于已有成果迭代）两种模式。

### 1.3 系统概述

本系统是一个基于大语言模型的多智能体软件开发平台，采用 LangGraph 作为核心框架，结合 AgentBay 提供的沙盒环境，构建了包含需求分析师、开发工程师和质量保证工程师三种角色的智能体团队。系统通过精心设计的协作流程和中间件机制，实现了软件需求的自动分析、功能点的迭代实现和代码质量的严格把控。

### 2.2 智能体团队架构

系统支持三种团队配置模式，以适应不同复杂度的开发任务：

#### 2.2.1 Simple 模式（三智能体团队）

包含三个专业智能体，形成完整的开发流水线：

- **Planner Alice**：负责需求分析和任务规划
- **Builder Bob**：负责代码实现和功能自测
- **Evaluator Eva**：负责验收标准评审和代码质量保证

协作流程：Alice 定义需求和功能点 → Bob 实现功能并自测 → Eva 评审 → Bob 根据反馈改进 → 循环直至完成

#### 2.2.2 Dual 模式（双智能体团队）

由 Builder 和 Evaluator 组成，适用于需求明确的场景：

- **Builder Bob**：同时承担需求分析和代码实现职责
- **Evaluator Eva**：负责质量评审和测试验证

#### 2.2.3 Single 模式（单智能体模式）

仅包含 Builder Bob，独立完成全部开发工作，适用于简单任务或快速原型开发。

### 2.3 核心组件设计

#### 2.3.1 AgentTeam 类

AgentTeam 是智能体团队的核心管理类，负责：

- 初始化团队配置和资源（沙盒、中间件、LLM）
- 创建和管理各智能体实例
- 处理绿地开发与棕地开发模式切换
- 管理异步资源（MCP工具、checkpointer）
- 自动下载成果物和清理会话资源

关键实现位于 [team.py](file:///d:/Python/VS%20Code%20WorkSpace/MAS_for_SD/src/dev_team/team.py)

#### 2.3.2 智能体角色定义

每个智能体通过系统提示词（System Prompt）定义其角色和职责：

- **Planner**：需求分析师，定义软件整体功能和功能点列表
- **Builder**：全栈开发工程师，实现软件功能点并进行自测
- **Evaluator**：质量保证工程师，评审验收标准和代码实现

提示词文件位于 [prompts_md_files](file:///d:/Python/VS%20Code%20WorkSpace/MAS_for_SD/src/prompts_md_files) 目录

#### 2.3.3 中间件体系

系统使用丰富的中间件来增强智能体能力：

- **MySkillsMiddleware**：技能加载中间件，支持渐进式披露模式
- **CommunicateMiddleware**：智能体间通信中间件，实现角色间对话
- **FilesystemMiddleware**：文件系统操作中间件，支持沙盒文件管理
- **AgentActivityMonitor**：智能体活动监控中间件
- **SystemPromptInjectMiddleware**：系统提示词注入中间件
- **UnicodeEncodeErrorHandlerMiddleware**：编码错误处理中间件

中间件实现位于 [custom_middleware](file:///d:/Python/VS%20Code%20WorkSpace/MAS_for_SD/src/custom_middleware) 目录

#### 2.3.4 技能系统

技能系统为智能体提供专业领域知识和操作指南：

- **python-full-stack-development**：Python全栈开发技能，包含虚拟环境创建、依赖管理、国内镜像源配置等
- **software-function-verification**：软件功能验证技能，指导测试用例编写和执行
- **software-engineering**：软件工程技能，涵盖编码规范和最佳实践
- **deliverables-check**：成果物检查技能，确保交付质量

技能文件位于 [agent_resources/skills](file:///d:/Python/VS%20Code%20WorkSpace/MAS_for_SD/src/agent_resources/skills) 目录

### 2.4 数据流程

#### 2.4.1 开发任务执行流程

```
用户输入需求
    │
```

- **InMemorySaver**：开发测试使用，轻量级内存存储

状态管理确保了开发过程的可追溯性和中断恢复能力。

## 3. 功能

### 3.1 需求分析功能

#### 3.1.1 需求接收与细化

系统能够接收用户原始需求描述，自动进行分析和细化：

- 支持模糊需求（如"开发一个贪吃蛇游戏"）
- 支持详细需求（包含技术约束和功能描述）
- 自动进行网络搜索以补充需求信息

#### 3.1.2 分层功能定义

根据用户需求，系统自动生成三个层次的软件功能定义：

- **基础版**：满足用户核心需求的最小功能集
- **进阶版**：在基础版之上增加增强功能
- **顶级版**：完整的功能实现

每个层次的定义遵循"UI、Runtime、Service、Repo、Config、Types"六层结构，仅关注用户可感知层。

#### 3.1.3 功能点分解

将软件功能定义拆解为可分步实现的功能点：

- 功能点具有明确的前后依赖关系
- 每个功能点可独立测试
- 功能点状态通过 TASKS.md 文件进行管理

### 3.2 代码实现功能

#### 3.2.1 开发环境管理

系统自动管理开发环境：

- 创建独立的项目虚拟环境
- 配置国内镜像源加速依赖安装
- 管理项目依赖包

#### 3.2.2 功能点实现

智能体自动完成代码实现：

- 根据功能点定义编写代码
- 遵循编码规范和分层架构
- 优先使用 Web 页面作为 UI 实现方式

#### 3.2.3 功能自测

实现代码后自动进行自测：

- 参照既定验收标准执行测试用例
- 确保每个测试用例通过
- 遇到问题可向评审智能体求助

### 3.3 质量保证功能

#### 3.3.1 验收标准评审

评审智能体对验收标准进行严格审查：

- 检查必要开发项是否完整
- 验证测试用例数量和粒度是否充足
- 确保测试用例可通过实际运行验证

#### 3.3.2 代码质量评审

对代码实现进行多维度评审：

- 命名规范检查（变量、方法、类、文件）
- 依赖结构检查（是否遵循六层架构）
- 逻辑正确性检查（边界情况、错误处理）

#### 3.3.3 测试用例复现

评审智能体独立复现测试用例：

- 验证测试流程与既定标准一致
- 确认测试结果与开发者自测结果一致
- 确保功能实现符合预期

### 3.4 智能体协作功能

#### 3.4.1 角色间通信

智能体通过专门的通信中间件进行协作：

- Planner 与 Builder 通信：传递需求和开发指令
- Builder 与 Evaluator 通信：协商验收标准和提交评审
- 支持多轮对话和反馈迭代

#### 3.4.2 进度管理

系统自动管理开发进度：

- 实时更新功能点状态（未完成/已完成）
- 支持断点续开发（棕地开发模式）
- 记录每次开发任务的 thread_id 和上下文

#### 3.4.3 成果物管理

任务完成后自动处理成果物：

- 下载代码和文档到本地仓库
- 清理云端沙盒会话
- 保留完整的开发记录

### 3.5 开发模式支持

#### 3.5.1 绿地开发模式

从零开始的全新开发：

- 创建新的项目工作空间
- 生成唯一的 thread_id 和上下文
- 完整执行需求分析到代码实现的全流程

#### 3.5.2 棕地开发模式

基于已有成果的迭代开发：

- 复用之前的 thread_id 和上下文
- 继续未完成的功能点开发
- 支持渐进式迭代和增量开发

## 5. 系统使用

### 5.1 环境配置

#### 5.1.1 安装依赖

```bash
# 创建虚拟环境
python -m venv .venv

# 激活虚拟环境（Windows）
.venv\Scripts\activate

# 激活虚拟环境（Linux/macOS）
source .venv/bin/activate

# 安装依赖（使用国内镜像）
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

#### 5.1.2 配置环境变量

创建 `.env` 文件，配置必要的 API 密钥：

```
# LLM API 配置
USE_PAID_LLM_API=false
CHATANYWHERE_OPENAI_API_KEY=your_api_key
CHATANYWHERE_OPENAI_BASE_URL=your_base_url
MINIMAX_API_KEY=your_minimax_key
MINIMAX_BASE_URL=your_minimax_url

# AgentBay 配置
WUYING_AGENTBAY_API_KEY=your_agentbay_key

# 数据库配置（如需使用 PostgreSQL）
USE_POSTGRES_CHECKPOINTER=true
POSTGRES_DB_USER=postgres
POSTGRES_DB_PASSWORD=postgres
POSTGRES_DB_HOST=localhost
POSTGRES_DB_PORT=5442
POSTGRES_DB_NAME=postgres

# LangSmith 配置（可选）
LANGSMITH_TRACING=true
LANGSMITH_API_KEY=your_langsmith_key
LANGSMITH_PROJECT=your_project_name
```

配置文件位于 [settings.py](file:///d:/Python/VS%20Code%20WorkSpace/MAS_for_SD/src/config/settings.py)

### 5.2 运行模式

#### 5.2.1 实验模式

实验模式用于批量执行预定义的软件开发任务：

```bash
python -m src.main
```

该模式执行 [main.py](file:///d:/Python/VS%20Code%20WorkSpace/MAS_for_SD/src/main.py) 中的 `experiment()` 函数，支持：

- 加载预定义的任务数据集
- 交互式选择任务执行方式（执行/跳过/退出）
- 选择绿地开发或棕地开发模式
- 自动记录实验日志和统计信息

#### 5.2.2 单智能体测试模式

用于测试单个智能体的行为：

```python

```

该模式允许用户选择特定的智能体角色进行交互式对话测试。

#### 5.2.3 消息重播模式

用于查看和分析智能体间的对话历史：


该模式从检查点中提取智能体的消息记录，用于调试和分析。

### 5.5 配置说明

#### 5.5.1 团队类型配置

通过 `team_type` 参数选择团队模式：

- `"simple"`：三智能体团队（Planner + Builder + Evaluator）
- `"dual"`：双智能体团队（Builder + Evaluator）
- `"single"`：单智能体模式（仅 Builder）

#### 5.5.2 开发模式配置

通过 `enable_brown` 参数控制开发模式：

- `true`：启用棕地开发检测，复用已有上下文
- `false`：强制绿地开发，创建新的上下文

#### 5.5.3 模型配置

通过 `USE_PAID_LLM_API` 参数选择模型类型：

- `true`：使用 MiniMax-M2.7 付费模型
- `false`：使用 ChatAnywhere 提供的免费模型
